## 🎯 Цель проекта
Закрепление практических навыков разработки серверных веб-приложений на чистом PHP (версии 8.4+) без использования фреймворков. В проекте реализованы: разделение логики и представления, валидация суперглобальных массивов, управление состоянием пользователя, безопасная работа с файловой системой, атомарная запись данных в JSON и пресечение уязвимостей (CSRF, XSS).

---

## 🔥 Ключевой функционал и меры безопасности

1. **Безопасная загрузка файлов:** 
   * Прием файлов строго методом `POST`.
   * Валидация системных ошибок через коды `UPLOAD_ERR_*`.
   * Ограничение размера файла (строго до 5 MiB).
   * Проверка реального MIME-типа файла по бинарной сигнатуре с помощью расширения `Fileinfo` (разрешен только `application/pdf`). Исходному расширению и полю `type` от браузера доверия нет.
2. **Изолированное хранилище:**
   * Загруженные работы сохраняются со случайным криптографическим именем (`random_bytes()`) в папку `var/uploads/`, расположенную вне публичного каталога (`public/`). Это исключает прямой HTTP-доступ и запуск вредоносных скриптов.
3. **Контролируемое скачивание:**
   * Скачивание отчетов реализовано через защищенный маршрут на базе бинарного потока `readfile()`. Доступ предоставляется только владельцу файла (`ownerId`), совпадение проверяется на сервере.
4. **Надежная СУБД на JSON:**
   * Хранение метаданных (ID, имя, размер, автор, дата) организовано в JSON-файле.
   * Конкурентная одновременная запись защищена механизмом эксклюзивной блокировки файлов `LOCK_EX`, предотвращая повреждение структуры базы данных.
5. **Защита от сетевых уязвимостей:**
   * **CSRF (Cross-Site Request Forgery):** Форма содержит скрытый криптографический токен, проверяемый сервером с помощью `hash_equals()`.
   * **XSS (Cross-Site Scripting):** Все динамические данные перед выводом в HTML-шаблонах принудительно экранируются через `htmlspecialchars()`.
   * **Повторная отправка:** Применен паттерн *Post-Redirect-Get (PRG)*. Обновление страницы (F5) после отправки не дублирует файлы.

## 📂 Рекомендуемая структура проекта

```text
lab7_portal/
├── public/                 # Публичный корень веб-сервера
│   ├── index.php           # Единая точка входа и маршрутизатор
│   └── assets/
│       └── style.css       # Стили интерфейса
├── src/                    # Модули серверной бизнес-логики (declare(strict_types=1))
│   ├── auth.php            # Сессии и имитация авторизации студента
│   ├── csrf.php            # Генерация и проверка защитных токенов
│   ├── database.php        # Атомарная работа с JSON-файлами (LOCK_EX)
│   └── uploader.php        # Валидация, Fileinfo и сохранение файлов
├── templates/              # Изолированные PHP-шаблоны представления
│   ├── header.php          # Верхняя часть страницы
│   ├── footer.php          # Нижняя часть страницы
│   ├── upload_form.php     # Форма загрузки с CSRF-токеном и Flash-уведомлениями
│   └── list.php            # Таблица отправленных работ текущего пользователя
├── var/                    # Защищенное внутреннее хранилище (вне доступа веб-сервера)
│   ├── data/               # submissions.json (база данных метаданных)
│   └── uploads/            # Каталог для бинарных PDF-файлов
├── .gitignore              # Исключение временных данных и загрузок из Git
└── README.md               # Документация проекта
```

## 💻 Требования к среде и запуск

* **Интерпретатор:** PHP 8.4 или новее (со строгой типизацией).
* **Расширения:** `session`, `json`, `fileinfo` (включены по умолчанию в XAMPP).
* **Окружение:** XAMPP Control Panel для Windows.

### Инструкция по развертыванию:
1. Склонируйте репозиторий или перенесите папку проекта в рабочий каталог веб-сервера: `C:\xampp\htdocs\lab7_portal`.
2. Запустите **XAMPP Control Panel** и нажмите кнопку **Start** напротив модуля **Apache**.
3. Убедитесь, что для папок внутри `var/` у сервера есть права на чтение и запись.
4. Откройте любой современный веб-браузер и перейдите по адресу:
   ```text
   http://localhost/lab7_portal/public/
   ```

## 🧪 Демонстрационные тестовые сценарии для защиты

При демонстрации проекта на защите используются следующие подготовленные кейсы:

| Категория теста | Что отправляем | Ожидаемый контролируемый результат |
| :--- | :--- | :--- |
| **Успешный сценарий** | Корректный файл `report.pdf` (размер 1.2 МБ) | Зеленый баннер об успехе, файл появляется в таблице истории с кнопкой скачивания. |
| **Пустое значение** | Отправка формы без выбранного файла | Валидация HTML5 блокирует отправку; сервер возвращает ошибку, если поле стерто. |
| **Превышение лимита** | Файл `big_book.pdf` размером 6.1 МБ | Красный баннер: *"Размер файла превышает допустимый лимит в 5 MiB."* |
| **Некорректный тип** | Файл `script.php` или `photo.png` | Расширение `Fileinfo` считывает реальный заголовок. Красный баннер: *"Разрешены только документы формата PDF."* |
| **Нарушение CSRF** | Отправка формы с измененным (через DevTools) токеном | Запрос отклоняется сервером. Баннер: *"Ошибка безопасности: невалидный CSRF-токен."* |
| **Атака на обход путей** | Попытка скачать файл по поддельному ID (`../database.php`) | Маршрутизатор фильтрует ID по базе данных JSON. Сервер возвращает код ответа `404 Not Found`. |
